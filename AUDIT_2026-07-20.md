## 3. Mismatches

### 3.1 🔴 CRITICAL — Manuscript Table 1 does not reproduce from any output file

This is the most serious finding in the audit.

The AUC table appears verbatim in `F1000Research_Draft_Chintala_2026_final.docx` (and `_corrected.docx`), captioned:

> "Table 1. Core classification performance (TCGA cohort, clean feature selection, 30-split mean AUC)"

## 7. Leakage-safety inspection

### 7.1 Authoritative pipeline — train-only confirmed

**`src/features.py`** — variance filter, lines 43–44:

```python
variance = X_train.var(axis=0)
top_genes = variance.nlargest(top_n).index
```

Computed on `X_train` only; the same gene list is then applied to `X_test` (line 51). ✅

**`src/features.py`** — scaler, lines 71–73:

```python
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled  = scaler.transform(X_test)
```

`fit_transform` on train, `transform` only on test. ✅

**`src/pipeline.py`** lines 119–133 — correct ordering: `train_test_split` → `select_high_variance_genes(X_train, X_test)` → `scale_features(...)`. Selection and scaling both occur strictly after the split. ✅

**`src/ablation.py`** — the ablation is a deliberate, correctly-constructed contrast. Unsupervised arm, lines 109/113:

```python
# ── Condition A: LEAKY — variance computed on full X before split ──
leaky_genes   = _select_top_variance(X, top_n)
# ── Condition B: CORRECT — variance computed on X_train only ──
correct_genes = _select_top_variance(X_train, top_n)
```

Supervised arm, lines 221/225:

```python
# ── LEAKY: F-score computed on full X, y before splitting ──
leaky_genes   = _select_top_f_score(X, y_arr, top_n)
# ── CORRECT: F-score computed on training fold only ──
correct_genes = _select_top_f_score(X_train, y_train, top_n)
```

In both arms the scaler is re-fit per condition inside the loop on `Xtr` only (lines 120–122, 232–234). The leaky condition is leaky *by construction*, which is the point of the experiment. ✅

### 7.2 phase2_03b bug — confirmed and superseded

`phase2_03b` computed the top-500 variance-filtered gene list on the **full platinum cohort** rather than per-threshold train-only data. Confirmed empirically by `phase2/outputs/phase2_03c_gene_set_diagnostic.csv`:

True per-threshold gene sets differ from each other and from the 03b list by **22–36 genes**, exactly as claimed. ✅ Superseded by `phase2_03d_cv_permutation_shap_importance.py` (2026-07-12), which computes per-threshold, train-only sets within `RepeatedStratifiedKFold`. Its outputs (`cv_*`) are the ones used for all Finding 5 numbers verified in §2.

### 7.3 Verdict — with one caveat

**The authoritative pipeline is leakage-free with respect to the held-out test set, as claimed.** Variance filtering and standardisation are both computed train-only, after the split, in `features.py`, `pipeline.py`, and both arms of `ablation.py`. The reported headline AUCs are not inflated by test-set leakage.

**One caveat you should know about, and it is not the leak the paper is about.** In `src/pipeline.py`, `cross_validate_model` is called at line 156 on `X_train_sc` — a matrix whose gene selection and scaler were fit on the *entire* training set, including each inner CV validation fold:

```python
X_train_sc, X_test_sc, scaler = scale_features(X_train_red, X_test_red)   # line 133
...
cv = cross_validate_model(trained, X_train_sc, y_train, ...)              # line 156
```

So any **cross-validation** score reported out of `pipeline.py` carries mild optimistic bias from within-training-set information sharing. This does **not** affect the held-out test AUCs, and it does **not** affect the ablation results in §2 (which re-fit per condition per split), nor the Finding 5 CV numbers (which come from `phase2_03d`, where selection is inside the fold). It is a limitation worth one sentence in Methods if any `pipeline.py` CV number appears in the manuscript. If none does, ignore it.
